# 6-Max Preflop Chart

A comprehensive 6-Max Cash Game preflop chart viewer with full offline support.

## Features

- **Fixed Position Order**: UTG / HJ / CO / BTN / SB / BB
- **Multiple Stacks**: Open and VS 3Bet ranges
- **Hover/Click Modes**: Choose your preferred interaction style
- **Full Offline Support**: Three-tier loading system ensures it works anywhere

## Usage

### Online (HTTP Server)

1. Serve the `6Max Chart` folder via any HTTP server
2. The chart will automatically load `manifest.json`
3. All images and stacks will be available

### Offline (File System) - With Pre-generated Manifests

1. Download and extract the release ZIP
2. Open `6Max Chart/index.html` directly in your browser
3. The embedded `manifest.js` will provide all images automatically
4. No server needed!

### Offline (File System) - Manual Folder Loading

If manifest files are missing or you have custom images:

1. Open `6Max Chart/index.html` in your browser
2. Click the "📁 Mappa betöltése" (Load Folder) button
3. Select the "6-Max Rangek" folder when prompted
4. All images will be loaded directly from your file system
5. No manifest files needed!

**Note**: The folder picker requires a modern browser with File System Access API support (Chrome 86+, Edge 86+, Opera 72+).

## Manifest Generation

To regenerate manifest files after adding/removing images:

```bash
node generate-manifest.js
```

This will create/update:
- `6Max Chart/manifest.json` - JSON manifest for HTTP servers
- `6Max Chart/manifest.js` - Embedded JavaScript manifest for offline use

## How It Works

The application uses a three-tier manifest loading system:

1. **Tier 1 (Offline with embedded manifest)**: If `window.__CHART_MANIFEST__` exists (loaded from `manifest.js`), use it
2. **Tier 2 (HTTP Server)**: Try to fetch `manifest.json` from the server
3. **Tier 3 (Minimal Fallback)**: Use minimal hardcoded manifest (only "Open" stacks)

When opened via `file://` protocol, the "Mappa betöltése" button appears, allowing users to manually load images using the File System Access API.

## Development

### CI/CD

The repository includes a GitHub Actions workflow that automatically regenerates manifest files when images change. The workflow:

1. Detects changes to PNG files in `6-Max Rangek/`
2. Runs `generate-manifest.js`
3. Commits updated manifest files back to the repository

### Adding New Images

1. Add PNG files to the appropriate position/stack folder
2. Commit and push changes
3. Manifests will be auto-generated by CI
4. Or run `node generate-manifest.js` locally
